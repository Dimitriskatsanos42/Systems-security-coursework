# 2η Εργασία — Secure File Storage System

Ασφαλές σύστημα αποθήκευσης αρχείων σε Python (CLI), υλοποιημένο πάνω στον starter
κώδικα της εκφώνησης (`secure_storage.py`) συμπληρώνοντας όλα τα σημεία `# TODO`.

Πανεπιστήμιο Ιωαννίνων — Τμήμα Πληροφορικής & Τηλεπικοινωνιών

## Λειτουργίες

- **Μέρος Α** — Hash & Salt κωδικών (PBKDF2-HMAC-SHA256, μέσω `cryptography`)
- **Μέρος Β** — Εγγραφή χρήστη με μονόχρηστο OTP
- **Μέρος Γ** — Αυθεντικοποίηση χρήστη (χωρίς διαρροή πληροφορίας για user enumeration)
- **Μέρος Δ** — Ζεύγος κλειδιών RSA-2048 (δόθηκε έτοιμο)
- **Μέρος Ε** — Προστασία από Replay Attacks μέσω μονόχρηστων nonces
- **Μέρος ΣΤ** — Κρυπτογράφηση AES-256-GCM + Ψηφιακή Υπογραφή RSA-PSS/SHA-256
- **Μέρος Ζ** — Upload / Download αρχείων + διαδραστικό CLI

## Εγκατάσταση

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Απαιτείται **Python 3.9+**.

## Εκτέλεση

```bash
python3 secure_storage.py
```

Διαδραστικό μενού:

```
1. Εγγραφή (με OTP)
2. Σύνδεση
3. Ανέβασμα αρχείου
4. Κατέβασμα αρχείου
9. Admin: Έκδοση OTP     <- βοηθητική επιλογή για testing
0. Έξοδος
```

### Τυπική ροή δοκιμής

1. Επιλογή **9** → δώσε ένα username (π.χ. `alice`) → σημείωσε το OTP που εμφανίζεται
2. Επιλογή **1** → δώσε το ίδιο username, το OTP, και έναν κωδικό
3. Επιλογή **2** → σύνδεση με τα ίδια στοιχεία
4. Επιλογή **3** → δώσε τη διαδρομή ενός τοπικού αρχείου προς ανέβασμα
5. Επιλογή **4** → δώσε το όνομα του αρχείου (χωρίς διαδρομή) για κατέβασμα — θα
   αποθηκευτεί ως `downloaded_<filename>`

## Δομή δεδομένων εκτέλεσης (δημιουργούνται αυτόματα, δεν παραδίδονται)

```
users.json         # χρήστες: password_hash, salt, created_at
otp_store.json      # εκδοθέντα OTP ανά χρήστη
nonces.json          # χρησιμοποιημένα nonces (anti-replay)
keys/                # RSA public/private keys ανά χρήστη (PEM)
secure_storage/      # κρυπτογραφημένα αρχεία (.enc) + μεταδεδομένα (.json)
```

Αυτοί οι φάκελοι/αρχεία εξαιρούνται ρητά από το repository (`.gitignore`), όπως
ζητά η εκφώνηση.

## Σημειώσεις Ασφάλειας

- Ο κωδικός αποθηκεύεται **μόνο ως hash+salt** (PBKDF2, 390.000 επαναλήψεις) — ποτέ σε
  απλό κείμενο.
- Η σύνδεση επιστρέφει το **ίδιο γενικό μήνυμα σφάλματος** είτε ο χρήστης δεν υπάρχει
  είτε ο κωδικός είναι λάθος, ώστε να μην είναι δυνατή η απαρίθμηση έγκυρων usernames.
- Κάθε upload παράγει **νέο τυχαίο κλειδί AES + nonce** — καμία επαναχρησιμοποίηση.
- Η ψηφιακή υπογραφή καλύπτει `data + nonce`, ώστε να συνδέεται με το συγκεκριμένο
  αίτημα (και όχι μόνο με το περιεχόμενο του αρχείου).
- Κάθε nonce χρησιμοποιείται μία μόνο φορά· η επανάληψή του θεωρείται replay attack
  και απορρίπτεται.
